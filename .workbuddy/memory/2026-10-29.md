# 2026-10-29

## 网址导航：Pan 的 tab 升级成大纲里的二级菜单（默认折叠）

**需求**：`/docs/收藏的网站/` 这页的 `MNavLinks` 本来只有 `h2`（分组名）进大纲，
`Pan` 组件上方的 tab 栏（前端 / 开发框架、UI组件库…）在右侧「当前页大纲」里看不见。
要求把这些 tab 也做成二级菜单。

### 关键发现：VitePress 的 outline 是**运行时扫 DOM**，不是读 pageData.headers

一开始想用 `config.mjs` 的 `transformPageData` 往 `pageData.headers` 里塞 h3，
**这条路是错的**。`theme-default/composables/outline.js` 里：

```js
export function getHeaders(range) {
  const headers = [...document.querySelectorAll('.VPDoc :where(h1,h2,h3,h4,h5,h6)')]
    .filter((el) => el.id && el.hasChildNodes())
    .map(...)
  return resolveHeaders(headers, range)
}
```

`VPDocAsideOutline` 在 `onContentUpdated`（由 `Content.js` 的 `onVnodeMounted` / `onVnodeUpdated` /
`watch(frontmatter)` 触发）里调用它。**所以只有真正的 heading 元素才会进菜单，给 div 设 id 完全没用。**

→ 结论：**把 tab 从 `<div class="tab-head-item">` 换成 `<h3 class="tab-head-item">`**
（`MNavLinks.vue`），其余什么都不用改。

### 换成 h3 的代价：要把 `.vp-doc h3` 的全局样式全部抹掉

`.vp-doc h3 { margin: 32px 0 0; font-size: 20px; font-weight: 600; letter-spacing: -0.01em; line-height: 28px; position: relative; outline: none }`
不重置的话 tab 条直接被撑变形。在 scoped 的 `.tab-head-item` 里补：

```scss
margin: 0; font-size: inherit; font-weight: 400; letter-spacing: normal;
```

scoped 编译后是 `.tab-head-item[data-v-x]`（0,2,0），高于 `.vp-doc h3`（0,1,1），能盖住；
但**没显式声明的属性会被全局规则接管**（比如 margin），所以必须一条条写出来。

### 锚点 id 必须和 outline 的 href 对得上

新建 `theme/utils/nav-headings.js`，用 `@mdit-vue/shared` 的 `slugify`（和 VitePress 内部同一套规则）：

- 分组（h2）：`slugify(title)` → 「实用工具」→ `实用工具`
- tab（h3）：`slugify(分组名 + ' ' + tab名)` → 「前端」+「开发框架」→ `前端-开发框架`
  **带分组前缀**，否则不同分组下的同名 tab 会撞车

实测 44 个锚点全部能 `getElementById` 命中。

### 交互

- 点 tab → `history.replaceState` 只改地址栏、**不滚动**（用户此刻就在 tab 旁边，跳一下反而突兀）
- 点大纲里的二级项 → 浏览器原生锚点导航 → `hashchange` → `syncFromHash()` 用 `decodeURIComponent(hash)` 反查 index，切到对应的 tab
- 带 `#前端-第三方工具库` 直接进来 → `onMounted` 里同样反查一次
- slider 的位移改成按 index 查 DOM（原来用 `e.target.offsetLeft`，点到内部节点会算错）

### 验证（CDP + dev server 5199）
- tab 元素：30 个全是 H3，无缺 id、无重复 id；高度 25px、字号 16px、字重 400、`margin-top: 0` → 视觉零变化
- 大纲：14 个一级项、30 个二级项、44 个链接，`missing: []`
- 点大纲「第三方工具库」→ tab 切换 + hash 同步 + 卡片从 Npmjs 变成对应内容
- 点大纲「游戏下载」→ `scrollY 3922`、目标顶到视口 134px、tab 激活、大纲高亮
- 点 tab「CDN」→ slider `835px` 精确等于激活项 `offsetLeft: 835px`
- 带 hash 直达 → 自动展开对应 tab

## 右上角大纲折叠（用户后续要求「二级菜单默认折叠」）

**为什么不能改组件**：`VPDocAside` 里是 `import VPDocAsideOutline from './VPDocAsideOutline.vue'`（本地导入），
`app.component('VPDocAsideOutline', ...)` **覆盖不了**，`aside-outline-before` 插槽也只能在内容前插节点。
所以只能等它渲染完再动 DOM。

**实现**：`theme/components/OutlineCollapse.vue`（挂在 `Layout.vue` 里，渲染一个 `hidden` 的 span），
`onMounted` + `onContentUpdated` → `nextTick` + `rAF` + 120ms 兜底，扫
`.VPDocAsideOutline .VPDocOutlineItem.root > li`，给有 `.nested` 的 li：
- 加 `has-children`
- 追加一个 `button.vp-outline-toggle`（绝对定位在 li 右侧，`aria-expanded` 跟着切）
- 用 `data-vp-collapse` 标记，避免重复插按钮

样式在 `theme/style/outline-collapse.css`（**必须全局**，不能 scoped）：

```css
li.has-children > .VPDocOutlineItem.nested { display: none }
li.has-children.is-open > .VPDocOutlineItem.nested { display: block }
li.has-children > .outline-link { padding-right: 20px }  /* 给箭头让位 */
```

**两个坑**
1. 箭头按钮是 li 的子元素，点在 li 里那个 `<a>` 上会冒泡触发跳转 → 必须 `preventDefault + stopPropagation`。
2. **折叠的二级项不会被滚动高亮选中**（`getAbsoluteTop` 对 `display:none` 返回 NaN，被 filter 掉），
   所以 marker 不会错位；但带 hash 直进时会 `activateLink(location.hash)` 点亮隐藏项 → 用
   `MutationObserver(root, { attributes:true, attributeFilter:['class'] })` 观察 active 变化，
   若 active 落在折叠的组里就自动展开它（**只监听 class，不监听 childList**，否则插按钮会自激）。

**验证**：导航页 8 个有子项的条目全部 `is-open: false`、`nested display: none`、可见二级项 0 个；
点箭头展开/收起正常；点一级标题会展开并跳转（scrollY 0 → 1817）；
SPA 路由连切 3 个文档页，每次都是 `expanded: 0`，`toggles` 数与 `withChildren` 一致。

## 修：滑块（.outline-marker）位置不对 —— 两个独立原因，都被踩过

### 原因一：自己给 li 加了 `position: relative`，把 offsetTop 的基准改掉了

**这是我自己引入的回归**。为了让箭头按钮能绝对定位，最初写了
`.root > li.has-children { position: relative }`。结果里面 `<a>` 的 `offsetParent`
从 `.content` 变成了 `li`，而 VitePress 的滑块定位是：

```js
marker.value.style.top = activeLink.offsetTop + 39 + 'px'   // 只有一层，不是累加
```

`offsetTop` 一旦变成「相对自己那一行」，滑块就飞了。实测偏差 **82px 到 670px**。

**修法**：不写 `position: relative`，改用 flex 排一行 —— 定位上下文一点都不用碰：

```css
.root > li.has-children { display: flex; flex-wrap: wrap; align-items: center }
.root > li.has-children > .outline-link { flex: 1 1 auto; min-width: 0 }
.root > li.has-children > .nested { flex: 0 0 100%; box-sizing: border-box }
.vp-outline-toggle { flex: 0 0 20px; height: 32px }
```

配套：按钮必须 `li.insertBefore(toggle, nested)`（原先是 appendChild，会排到子列表后面，
flex 下顺序就错了）。改完 `offsetParent` 回到 `ul.root`（VitePress 给它设了 relative），滑块归位。

> 记住：`getAbsoluteTop()` 里是**累加** offsetTop 的，所以滚动判定一直是对的；
> 只有 `activateLink` 里那一层裸 `offsetTop` 会坏。看到「滑块飘了但高亮对了」就是这个。

### 原因二：同一行多个标题，VitePress 只会点亮最后一个

网址导航页一排 9 个 tab，它们的 h3 **垂直坐标完全相同**。`setActiveLink()` 里：

```js
for (const { link, top } of headers) {
  if (top > scrollY + getScrollOffset() + 4) break
  activeLink = link          // 同 top 时后者覆盖前者
}
```

于是点「UI组件库」，高亮落在这一排最后的「CDN」上。这个判定改不了（headers 是 DOM 扫描出来的，
同一 y 坐标没法区分）。**只能在点击之后把高亮纠正回真正被点的那一项。**

`OutlineCollapse.vue` 里加了 `pinTo(link)`：点大纲链接 / hashchange 时，
在 160ms 和 400ms 各纠正一次（VitePress 的滚动高亮是节流 100ms + 停止后 100ms 再算一次，
必须落在它后面）。纠正 = 清掉其他 `.active` + 给目标加 `.active` + `syncMarker()`。

同时 `syncMarker(active)` 改成用 `getBoundingClientRect()` 直接算：

```js
marker.style.top = `${Math.round(box.top - base.top + (box.height - marker.offsetHeight) / 2)}px`
```

比 `offsetTop + 39` 那个魔数稳，也不用管 offsetParent 链。实测 delta 从 ±82~702 变成 0。

### 附带修的一个生命周期 bug

`observe()` 原来写的是 `if (!root || observer) return` —— 路由切换后 outline 整棵被替换，
observer 还挂在已移除的旧节点上，新的 root 没人观察。改成记 `observedRoot`，节点变了重新挂。

**最终回归（5 项全 PASS）**：
导航页默认全折叠 → 点「可视化」→ 点「知识学习」→ SPA 到文档页默认全折叠 → 点最后一个二级项「1.2.2 返回值」，
每次 `active` 都是被点的那一项，`markerDelta` 都是 0。

## 已知限制（改不掉的）

- 用户点完二级项之后再手动滚动，VitePress 会重新按位置判定，高亮又回到这一排最后一项。
  只有「点」这个动作能被纠正，「滚」不行。
- 点 tab 本身走的是 `history.replaceState`，不触发 hashchange，所以大纲高亮不会跟着动。
- 导航页有 `Hydration completed but contains mismatches.`（index 与普通文档页都没有），
  怀疑是 `Pan.vue` 的 `el-tooltip`（构建日志里 `ElementPlusError: [IdInjection]`），未修，不影响显示。

## 折叠范围收窄：只有网址导航页折叠，其它页面保持全展开

用户明确要求「只有网址导航这一个页面的二级菜单要默认折叠，其他页面的多级菜单默认都展开」。

**用 frontmatter 开关，不要用路径判断**。`docs/docs/收藏的网站/index.md` 加：

```yaml
outlineCollapse: true
```

组件里 `const { frontmatter } = useData()`，`enabled = () => !!frontmatter.value.outlineCollapse`。
好处：声明式、换目录不失效、以后别的页面想折叠加一行就行。

### 三处要跟着改，漏一处就会串

1. **JS**：`run()` 里 `if (!enabled()) { reset(); return }`，enabled 时才 `decorate/observe`。
   `pinTo` 也要加守卫（普通页面大纲是竖排的，同 y 坐标问题不存在，不该干预）。
2. **CSS**：所有规则都加 `html[data-outline-collapse]` 前缀。这个属性由 JS 随 frontmatter
   在 `<html>` 上增删。**不能只靠「非折叠页不加 has-children 这个 class」** —— 见下一条。
3. **必须写 `reset()`**。`VPDocOutlineItem` 的 `v-for` **没有 key**，路由切换时 Vue 按 index 复用
   `<li>`，从 14 个 li 的导航页切到 4 个 li 的文档页时，前 4 个 li 连同我们插的按钮、
   `data-vp-collapse`、`has-children`、`is-open` 全部残留。`reset()` 要清掉：
   按钮节点、两个 data 属性、`has-children`/`is-open` class、observer、html 上的 flag。

**回归（5 项全 PASS）**：
导航页 `htmlFlag:true`、8 个箭头、`visibleNested:0`、`liDisplay:flex` →
文档页直开 `htmlFlag:false`、`toggles:0`、`visibleNested 26/26`、`liDisplay:list-item` →
SPA 导航页→文档页 无残留 → 文档页之间 SPA 全展开 → SPA 回导航页重新折叠 →
导航页点二级项「可视化」`active` 正确、`markerDelta:0`。
