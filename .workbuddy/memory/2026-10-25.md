## 新增 VitePress 插件：单击行内 code 即复制

**需求澄清**：用户最初说「所有代码块，也就是 `code` 格式的内容」，我理解成围栏代码块（三个反引号）写错了。
他要的是**行内 code（单个反引号）**：`doc` 里写成 `` `xxx` ``，渲染成 `.vp-doc :not(pre) > code`。

**文件**：`docs/.vitepress/theme/plugins/code-click-copy.js`
**注册**：`docs/.vitepress/theme/index.js` 的 `enhanceApp` → `app.use(codeClickCopy())`
**配置**：
```js
app.use(codeClickCopy({
  inlineCode: true,      // 行内 `code`（默认开）
  codeBlock: false,      // 围栏代码块（默认关，整块误触代价大）
  feedbackDuration: 900,
  cursor: 'copy',        // 传 'text' 还原选字光标
  copiedText: '已复制',
  failedText: '复制失败',
}))
```

### 关键实现决定（改之前先读）

1. **行内 code 取 `textContent`，围栏代码块取 `innerText`。**
   代码里的连续空格必须原样保留，`innerText` 走渲染结果、会按 CSS 折叠空白。
   实测同一个元素：`textContent === "a    b   \t c"`，`innerText === "a b c"` —— 用错就丢空格。
   反过来围栏代码块必须用 `innerText`（Shiki 每行一个 `<span class="line">`，`textContent` 会把所有行拼成一行）。

2. **行内 code 是 inline 元素，塞不下绝对定位气泡。**
   气泡改成挂在 `body` 上的 `position: fixed` **单例**，按 `getBoundingClientRect()` 摆到元素正上方
   （`gap 6px`；`rect.top <= 44` 时翻到下方），左右各留 40px 防溢出视口。
   围栏代码块是块级、容器 `position: relative`，继续用 `::after` 画在容器右上角（`right:58px` 避开自带复制按钮）。

3. **必须放过「用户正在选字」的情况。**
   拖选后松手会补一个 `click`，双击选词也会。判据：`getSelection()` 非空且 `!isCollapsed` 就 return，
   再拿 `event.detail > 1` 挡多击。**行内 code 很短，双击选它比代码块常见得多**，这条尤其重要。

4. **链接里的行内 code 不能抢。**
   `` [`foo`](./x.md) `` 渲染成 `<a><code>foo</code></a>`，点它是跳转。
   JS 里命中前 `node.closest('a, button, input, ...')` 直接 return；CSS 里把 `.vp-doc a > code` 的
   `cursor` 改回 `pointer`、`box-shadow` 清掉。

5. **事件委托挂在 `document` 上**，不在 DOMContentLoaded 逐个 `<code>` 绑。
   VitePress 是 SPA，切路由整片换 DOM，委托不用重绑，也免疫异步渲染。

6. **SSR**：`enhanceApp` 在服务端也会执行，`install()` 第一句 `typeof window === 'undefined'` 返回。

### 视觉
- 行内 code：`cursor: copy` + hover 一圈 `box-shadow: 0 0 0 1px var(--vp-c-brand-1)`（告诉用户能点）；
  点击后**反色**（品牌色底 + 白字）900ms。
- 行内 code 的 `transition` 可以自己写（VitePress 没给它设）；**围栏代码块的容器不能加 transition** ——
  `.vp-doc div[class*='language-']` 已被 VitePress 占了 `transition: background-color .5s` 且特异性更高（0,2,1 vs 0,1,1），
  加不进去，所以描边只能瞬显。

## 修复：线上首页魔方被放大 4 倍、盖住首屏（hydration mismatch）

**现象**：GitHub Pages 上线后，首页 `<div class="image">`（固定 500px 高）里的魔方偶尔变成整页高，
canvas 实测 `attr 2304×4372 / css 1152×2186`，把下面的内容全盖住。刷新几次有时好有时坏 → 典型的**概率性**渲染 bug。

**排查路径（可复用）**
1. 比对 `Last-Modified` 与本地 commit，确认线上产物是最新的，排除「部署没生效」。
2. 抓线上 CSS 确认 `.rubik{position:relative;height:100%}`、`.home .image[data-v-*]{height:500px;overflow:hidden}` 都在 → 样式没丢，是 DOM 结构不对。
3. 单次打开完全正常 → 必须**反复刷新**才复现。CDP 连刷 16~24 次统计，冷缓存（`Network.setCacheDisabled`）复现率明显更高。
4. 抓到异常那一轮的 DOM，根因立刻清楚：
   ```html
   <div id="container" data-v-b6d71930>      <!-- GlassBox 的根节点！ -->
     <div class="rubik__stage">…<canvas width="2304" height="4372">
     <div class="rubik__toolbar">
   ```
   根元素是 **GlassBox 的 `<div id="container">`**，里面却塞了 Rubik 的子节点，而且**没有 `class="rubik"`**。

**根因**
`Home.vue` 的 `componentName = shallowRef(Rubik)`，`randomBox()` 在 `setup()` 里**随机**从
`[Circle, GlassBox, Rubik, AnimationModel]` 选一个。SSR 随机一次、客户端水合时再随机一次，
两边选到不同组件时 Vue 会**复用 SSR 那棵 DOM 的根元素**，只把新组件的子节点塞进去 ——
根元素的 `class` 保持旧组件的。于是 `<component :is>` 的根节点丢了 `class="rubik"`。

后果是连锁的（记住这条 CSS 规则）：
`.rubik{position:relative}` 没了 → `.rubik__stage{position:absolute;inset:0}` 的**包含块**没了
→ 因为 `position:static` 的祖先不建立包含块，绝对定位元素一路向上找到 `body`
→ canvas 按整页高度撑开。**没有 `transform`/`filter` 的 static 元素不建立包含块**，这是这次放大的直接原因。

**修法**（`Home.vue`，两层保险）
1. **根因**：`<ClientOnly>` 包住 `<component :is="componentName" />`（VitePress 已全局注册）。
   这几张 canvas 本来就没法 SSR，跳过服务端渲染既消除水合不一致，也不会有布局跳动（`.image` 有固定 500px 高）。
2. **兜底**：`.image` 加 `position: relative` + `overflow: hidden`。
   即使将来组件的 class 因为任何原因再失效，stage 最多被裁成 500px，不会再撑破首屏。

**验证**：本地生产构建（约 160s），CDP 冷缓存连刷 24 轮、四种 box 轮换，全部 `imgH:500 / cvH:500`、`bad: null`。
修复前同一脚本在线上跑，第 16 轮 `box=rubik` 必现 `cvH:2186`。

**教训**：`setup()` 里用 `Math.random()` 选组件 = 水合地雷。凡是随机/时间/`window` 决定的**结构**（不是数据），
一律 `<ClientOnly>` 或延迟到 `onMounted` 再赋值。
