# Index和IndexMut

`Index`和`IndexMut`是两个存在于`std::ops`中的`trait`，规定了数组、切片、`Vec`等数据类型访问元素的方式

`Index`的定义如下

```rust
pub trait Index<Idx>
where
    Idx: ?Sized,
{
    type Output: ?Sized;

    // Required method
    fn index(&self, index: Idx) -> &Self::Output;
}
```

`IndexMut`的定义如下

```rust
pub trait IndexMut<Idx>: Index<Idx>
where
    Idx: ?Sized,
{
    // Required method
    fn index_mut(&mut self, index: Idx) -> &mut Self::Output;
}
```

可以看到，`IndexMut`继承了`Index`，也就是说两者都有一个关联类型`Output`，规定了通过下标获取元素时返回值的类型

- `index`方法获取指定索引处元素的**不可变引用**
- `index_mut`方法获取指定索引处元素的**可变引用**

并且这两个都没有默认实现，实现了这两个`Trait`的类型必须手动实现这两个方法



## arr[index]访问的实质

当我们使用索引访问元素的时候，实际上是调用了`index`和`index_mut`方法的语法糖

当我们使用[index]去访问数组元素时

```rust
fn main() {
    let arr = [10, 20, 30];
    let mut arr1 = [40, 50, 60];

    let x = arr[2];

    arr1[2] += 10;
    let y = arr1[2];

    println!("{},{}", x, y); // 30,70
}
```

实际上相当于

```rust
use std::ops::{Index, IndexMut};

fn main() {
    let arr = [10, 20, 30];
    let mut arr1 = [40, 50, 60];

    let x = *arr.index(2);

    *arr1.index_mut(2) += 10;
    let y = *arr1.index_mut(2);

    println!("{},{}", x, y); // 30,70
}
```

因为`index`和`index_mut`是`ops`里面的，而且没有包含在`prelude`，所以需要`use`导入一下



:::tip

当使用`index`和`index_mut`获取元素的值时，发现去掉`*`，结果也和我们预想的一样

```rust
use std::ops::{Index, IndexMut};
fn main() {
    let arr = [10, 20, 30];
    let mut arr1 = [40, 50, 60];

    let x = arr.index(2);

    let y = arr1.index_mut(2);

    println!("{},{}", x, y); // 30,60
}
```

我们可以注意vscode给我们的类型推导

## arr[index]的使用限制

如果数组的元素的类型实现 `Copy`，那么当使用`let value = v[index]` 这样的语法赋值时，将会按位赋值

但是如果输入元素未实现`Copy`，就只能获取到元素的引用

```rust
fn main() {
    let arr = [
        String::from("123"),
        String::from("456"),
        String::from("789"),
    ];
    let s = arr[1];  // 报错：cannot move out of here
}
```

如上所示，直接赋值的话会提示不能在此移动

那么我们只能使用借用的方式

```rust
fn main() {
    let arr = [
        String::from("123"),
        String::from("456"),
        String::from("789"),
    ];
    let s = &arr[1];
}
```





## 运算符重载

在`rust`中，不同类型使用`[]`访问其中元素，是一种运算符重载

在`std::ops`，规定了很多运算符重载的方式，`Index`和`IndexMut`就是对`[]`运算符重载的定义，规定了我们若想自定义`[]`重载，该如何定义

只有实现了`Index`和`IndexMut`这两个Trait的类型，才可以对`[]`运算符重载，比如数组的实现定义

```rust
impl<T, I, const N: usize> Index<I> for [T; N]
where
    [T]: Index<I>,
{
    type Output = <[T] as Index<I>>::Output;

    #[inline]
    fn index(&self, index: I) -> &Self::Output {
        Index::index(self as &[T], index)
    }
}
```

- `[T; N]`：在rust中数组的类型就是`[T; N]`，没有专门的`array`类型
- `[T]: Index<I>`：只有当切片 `[T]`实现了 `Index<I>`时，数组 `[T; N]`才能实现 `Index<I>`。
- `type Output = <[T] as Index<I>>::Output;`：数组索引的返回类型，和切片索引的返回类型一模一样
- `#[inline]`：**内联该函数**，索引操作非常高频，内联可消除函数调用开销





## 给自己的类型实现Index

来自官方的示例

```rust
use std::ops::Index;

enum Nucleotide {
    A,
    C,
    G,
    T,
}

struct NucleotideCount {
    a: usize,
    c: usize,
    g: usize,
    t: usize,
}

impl Index<Nucleotide> for NucleotideCount {
    type Output = usize;

    fn index(&self, nucleotide: Nucleotide) -> &Self::Output {
        match nucleotide {
            Nucleotide::A => &self.a,
            Nucleotide::C => &self.c,
            Nucleotide::G => &self.g,
            Nucleotide::T => &self.t,
        }
    }
}

let nucleotide_count = NucleotideCount {a: 14, c: 9, g: 10, t: 12};
assert_eq!(nucleotide_count[Nucleotide::A], 14);
assert_eq!(nucleotide_count[Nucleotide::C], 9);
assert_eq!(nucleotide_count[Nucleotide::G], 10);
assert_eq!(nucleotide_count[Nucleotide::T], 12);
```
