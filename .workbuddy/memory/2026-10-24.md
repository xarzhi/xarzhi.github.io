## 生产构建才暴露的三个坑（dev 下都看不到，务必记住）

### 1. `<component :is>` 动态组件的 scoped 样式在 SSR 下整体失效
现象：`vitepress build` 出来的首页魔方巨大、铺满全屏；dev 完全正常。
根因：产物 CSS 是 `.rubik[data-v-9381e0da]{...}`，但 SSR 渲染出的 DOM 是 `<div class="rubik is-interactive">`，
**没有 `data-v-*` 属性** —— 动态组件在 SSR 阶段丢了 scopeId，导致 Rubik 的样式一条都不匹配。
后果：`.rubik` 的 `position:relative / height:100%` 全丢，绝对定位的 `.rubik__stage` 改为相对 body，
被撑成整个文档高度（实测 2186px）。

修法：`Rubik.vue` 的 `<style>` **去掉 scoped**（类名已统一 `rubik__` 前缀，不会冲突），并去掉所有 `:deep()`。
> 注意 `Circle.vue` 没有 style、`GlassBox.vue` 的 style 是空的，所以只有 Rubik 中招。

### 2. `renderer.setSize(w,h)` 默认会写死 canvas 的 inline 宽高 → 自我强化错误
生产环境 CSS 是外链，组件可能比样式表先挂载，首次 `resize()` 会读到「样式未生效」的巨大高度；
`setSize` 又把 `width/height` 写进 canvas 的 inline style，canvas 反过来把容器撑大，之后很难恢复。
修法：`renderer.setSize(width, height, false)` + CSS `.rubik__stage canvas { width:100%; height:100% }`，
显示尺寸完全交给 CSS；再在 `window.load` 后补一次 `resize()` 校准相机比例。

### 3. 绝对定位 + `<p>` 的默认 margin 会让元素重叠
`.rubik__hint` 写了 `margin:0`，但被全局 `.vp-doc p` 的 margin 压过（优先级更低）；
而且绝对定位的 `bottom` 是按 **margin box** 计算的，实测 hint 底边比预期高 16px，正好压在「打乱/复位」按钮上。
修法：把按钮和提示放进同一个 `.rubik__footer`（`position:absolute` + `flex-direction:column` + `gap:6px`），
两者按正常文档流排列；hint 用 `margin: 0 !important` 压住全局样式。

## 构建验证的坑（关键）

**`vitepress build` 在本机会失败，但与项目代码无关：**
```

  at checkBulkDeleteGuard (.../cli/vendor/shim/node-safe-delete-shim.cjs)
  at rimrafWindowsDir (vitepress/dist/node/chunk-*.js)
```
VitePress 构建前会 `rimraf` 清空 `docs/.vitepress/.temp`（md→js 中间产物，上千个文件），

否则进程 hang 被 kill 后缓冲区里的错误就没了。

## 魔方「一步一复原」按钮（第二轮）

### 实现
- `rubiks.ts`：`begin()` 里记录 `history`（只记真正开始转的，队列里没执行的丢弃）；
  `solve()` 把 history 逆序 + 方向取反，交给 `solveSteps`；
  `update()` 里 **等 `active` 为空才启动下一步**（所以是一步一步，每步 `SOLVE_STEP_DURATION=0.3s`）。
  导出 `solve(onDone) / isSolving() / hasHistory()`。`reset()` 会清空历史并触发 `onDone`。
- `Rubik.vue`：右上角 `复原` 按钮（定位 `translate(calc(-50% + 185px), calc(-50% - 158px))`，
  落在魔方本体右上角外侧）；复原期间 `solving` 为真 → canvas `pointer-events:none`、
  `controls.enabled=false`、`pointerdown`/`keydown` 直接 return、两个底部按钮 disabled。

### 踩到的坑（重要）
1. **`cubeRef.current` 根本不存在** —— 这是 React `useRef().current` 的习惯，
   Vue 的 `ref/shallowRef` 是 `.value`。写成 `.current` 后 `?.` 会静默短路，
   表现为「点按钮完全没反应」，而且不报错，极难查。
   > 判断依据：`defineExpose` 暴露的 `scramble` 存在、vnode props 里也有 `onClick`，
   > 但点了就是没效果 → 一定是函数体内访问实例失败。
2. **`canRestore` 不要只靠渲染循环轮询**：`tick()` 里读 `hasHistory()` 更新按钮状态，
   在后台标签页/不可见时 rAF 会停，状态就不更新。改成在 `scramble/reset/turn/rotate`
   这些操作入口直接赋值，tick 只做兜底。
3. **headless 验证 WebGL 动画的姿势**：
   - `--virtual-time-budget` 会快进定时器**但不推进 `requestAnimationFrame`**，
     所以 three 的转动永远停在原地，测出来全是"没反应"，是假阴性。
   - 正确做法：`--remote-debugging-port` + CDP（Node 22 内置 WebSocket），真实时间驱动；
     并且 headless 下首屏要 30-60 秒，必须**轮询 `document.querySelector` 就绪**再操作。
   - 按钮是否可点，用 `dispatchEvent(new MouseEvent('click',{bubbles:true,clientX,clientY}))`，
     **别用 `.click()`**：`clientX` 为 0 会踩到 `useClickParticles.js:71` 的
     `e.clientX || e.touches[0].clientX`（MouseEvent 没有 touches）抛错。

### 既有隐患（本次未改）
`docs/.vitepress/theme/hooks/useClickParticles.js:71`：`(e.clientX || e.touches[0].clientX)`，
`clientX === 0` 时会 `Cannot read properties of undefined`，点击粒子特效中断。真实点击极少触发。

## 雷姆看板娘：点击不说话 —— 根因与修复

### 现象
点击看板娘只有气泡换文案，模型完全不动、也没有声音。

### 根因（两条，互相独立）
1. **模型缺少标准 `hit_areas` 字段** → 点击命中永远为空 → 什么都不会发生。
   `rem.model.json` 里只有 `hit_areas_custom`（`head_x/head_y/body_x/body_y` 归一化矩形，
   是某些旧播放器的私有格式），而 oh-my-live2d 用的是 pixi-live2d-display，只读 `hit_areas`。
   oml2d 的链路（压缩代码里逐行确认过）：
   ```
   model.tap(x,y) → internalModel.hitTest() → this.hitAreas（来自 settings.hitAreas ← model.json 的 hit_areas）
   命中才 emit('hit') → oml2d: model.on('hit', n => playRandomMotion(n))
   ```
   `setupHitAreas()` 里有 `filter(e => e.index >= 0)`，`getDrawDataIndex` 找不到的 id 会被静默丢弃，
   表现为「配了 hit_areas 也没反应」，很容易误判成配置没生效。
2. **模型包里 0 个音频文件**，34 个 mtn 里也没有 `sound` 字段 → 就算动作播了也不会出声。
   另外 `volume: 0` 也是静音，两层都要改。

### 真实的 drawable id（关键）
- `D_REF.PT_HEAD`（index 0）、`D_REF.PT_BODY`（index 1）—— Cubism 模型规范里前两个 drawable 就是命中参考。
- **别用从 moc 二进制里正则扫 ASCII 字符串的办法**：相邻字符串会粘连，我一开始扫出
  `D_REF.PT_HEAD3` / `D_REF.PT_BODY!`（多粘了一个字符），全部 `getDrawDataIndex` 返回 -1。
- 正确做法：页面里 `coreModel.getModelContext()` → `ctx.getDrawData(i).getDrawDataID().getString()`，
  `i` 从 `internalModel.drawDataCount`（本模型 120）枚举。
  注意 Cubism2 的 `coreModel` **没有** `getDrawableIds`，也没有枚举方法，只能这样拿。

### oml2d 的命中区 → 动作分组映射
```js
playRandomMotion(areas) {
  const keys = Object.keys(motionGroups)   // ['idle','flick_head','tap_body','sleepy','rest','talk']
  let g = keys.find(k => areas[0].includes(k.toLowerCase()) || k.toLowerCase().includes(areas[0]))
  g ||= 随机一个
  this.playMotion(g)
}
```
所以 `hit_areas` 的 `name` 写 `head` → 匹配 `flick_head`；写 `body` → 匹配 `tap_body`。

### 语音资源
- 来源：`imuncle/live2d` 仓库（codeload zip，master 分支，实际 479MB）。
  其中 `model/rem/voice/01.wav … 26.wav` 就是雷姆语音，**与 `Live2D_remu01.mtn…26.mtn` 一一对应**。
- 压缩：`ffmpeg -i x.wav -codec:a libmp3lame -ar 22050 -ac 1 -b:a 64k x.mp3`
  （原 5.3MB wav → 1.1MB mp3，26 个）。
- 落到 `docs/public/live2d/rem/assets/voice/NN.mp3`，model.json 里每个 motion 加
  `"sound": "voice/NN.mp3"`（路径相对 model.json）。共 51/54 个动作绑上了音频
  （idle/sleepy/rest 共用 remu_idle.mtn，没有对应语音）。
- `volume: 0` → `0.6`，否则照样静音。

### 网络（本机）
- `raw.githubusercontent.com` 不通；`cdn.jsdelivr.net` 对大仓库返回 **403（>50MB）**。
- **`https://gh-proxy.com/https://raw.githubusercontent.com/...` 和 `https://ghfast.top/...` 可用**；
  `codeload.github.com` 的 zip 也能用 gh-proxy 下。
- `api.github.com` 直连不通，走 gh-proxy 会撞 rate limit。

### 调试技巧
- `models[].showHitAreaFrames: true` 会在模型上把命中区画成红/绿框（还带名字），
  是判断「hit_areas 有没有被解析」最快的手段，比读内部状态直观。
- 验证是否出声：CDP `Network.enable` 抓 `.mp3` 请求 + hook
  `HTMLMediaElement.prototype.play`，能拿到 src / volume / status(206)。
  比听声音可靠（headless 没有音频输出）。
- headless 里读 `getBoundingClientRect()` 要等模型真正初始化完，否则会拿到
  未布局的坐标（实测读到 top=2085 这种值，点击自然打空）。要轮询到
  `motionManager.state.currentGroup` 有值且 rect.top 合理再点。

## 魔方复原改成「层先法（LBL）」—— 不再回放历史（第三轮，最终版）

用户要求：`魔方的复原能不能采用市面上的公式复原，而不是按照原来的步骤复原`。

### 结构
- **新增 `docs/.vitepress/theme/three/solver.ts`**：纯逻辑 3×3 模型 + 层先法求解器，**不依赖 three**，
  可单独在 Node 里跑（esbuild 打包成 cjs 直接测）。
- `rubiks.ts` 只负责把 `solveCube(logic)` 算出的 `Move[]` 播成动画；`logic` 在 `finish()` 里
  随每次真实转动同步（自动复原 / 打乱 / 拖拽三条路径共用同一个 `turnAxis`），所以求解器看到的就是画面上的局面。
- 对外 API：`solve(onDone) => 步数`、`isSolving()`、`isSolved()`（替代原来的 `hasHistory()`）。

### 状态表示（关键，别改）
- 每个块 `{ home, colors, pos, rot }`，`rot` 是 3×3 整数旋转矩阵（行主序，-1/0/1），
  `stickerDir(piece,color) = rot · NORMAL[color]`。
- 右手定则：绕 +axis 转 +90° 即 `dir=+1`；`FACE_TURN = R:{x,1,-1} L:{x,-1,1} U:{y,1,-1} D:{y,-1,1} F:{z,1,-1} B:{z,-1,1}`。
- **`slotFaces` 必须用 `法线·位置 === 1` 判断，不能用 `Math.abs(...) === 1`**：
  绝对值会让 `(-1,0,-1)` 同时命中 R 和 L，棱块朝向编码全乱（表现为 BFS 状态表与真实状态 76/80 不一致）。
- 中心块只有一色，转动时 `rot ≠ I` 但外观不变 → `isPieceSolved` 对 `colors.length === 1` 只比位置。
- `isSolvedUpToRotation`（每面同色即可）：拖拽中层相当于整体旋转，只用面转动回不到「白朝上」那个唯一朝向。

### 七步与所用公式
白色在**顶**，市面公式都是白色在底 → 统一 `mirrorAlg()`（U↔D 且 amount↔4-amount）后使用。
1. 底十字：4 条白棱压缩成 24 种状态（槽位×2+朝向），24⁴ = 331776 空间 BFS（`Int32Array` parent 表 + 18 个转动的映射表预计算）
2. 底角：`R' D' R` / `F D F'` / `R' D R F D2 F'` 三种插入 + `R' D R` 挤出
3. 中棱：`U R U' R' U' F' U F` / `U' F' U F U R U' R'`，`conjAlg(formula, yRotation(k))` 搬到四个槽位
4. 顶棱面位：`F R U R' U' F'`
5. 顶角面位：`R' D' R D` 循环
6. 顶角归位：`U R U' L' U R' U' L`
7. 顶棱归位：`R U' R U R U R U' R' U' R2`

### 踩到的三个坑
1. **`tryProgram` 里不能硬编码 F2L 检查**：底角阶段前两层本就未完成，会判所有候选失败
   （报「底角插入失败」）。改成只 `check(probe)`，顶层三步用 `withF2L(check)` 包一层。
2. **顶层候选必须按总步数排序后逐个试**：按枚举顺序先命中长解，解法会 200+ 步。
   并且把 `invertAlg(formula)` 也加入候选 —— 三循环换方向常能少做一两遍（顶棱面位 10.0→7.7 步）。
3. **候选要枚举「Dᵃ 公式 Dᵇ 公式 …」的所有 offset 组合（4^(reps+1)）**：
   只允许固定 D 偏移会漏掉「点→L→一字→十字」这种需要换着摆的连招。

### `reset()` 的顺序 bug（已修）
原来先 `logic = createSolvedState()` 再 `finish()`，而 `finish()` 会把「正在转的那一层」补转到 logic 上
→ 刚复位的魔方逻辑状态立刻歪一格，`isSolved()` 返回 false，「复原」按钮永远不置灰。
正确顺序：`finish()`（落位、归还 pivot）→ `logic = createSolvedState()` → 还原 cubie 变换。

### 播放节奏
`solveStepDuration(playLength) = clamp(8 / playLength, 0.04, 0.22)`，
`playLength` 用**展开后的步数**（180° 拆成两个 90°），否则实际播放比预期长。
注意 60fps 下每步会被向上取整到整帧，实测 169 步 ≈ 11s（比名义 8s 长，属正常）。

### 验证手段（可复用）
- **three 的场景图/几何体在 Node 里不需要 WebGL**：`esbuild --platform=node` 打包
  `rubiks.ts` 后用 `cube.update(1/60)` 循环驱动，就能端到端验证 `scramble → solve → isSolved`
  以及 `reset` 途中打断，比 CDP 截图可靠得多。
- esbuild 打包到 `--format=cjs` 时**不能用顶层 `await import()`**（会静默失败、复用旧产物）；
  校验脚本要把失败信息写进报告文件，否则会误以为「改的代码没生效」。
