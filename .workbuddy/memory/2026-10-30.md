# 2026-10-30

## three.js 组件「切标签页再回来就假死」——同一 bug 出现在两处

**症状**：切到别的浏览器标签页再切回来，魔方 / AnimationModel 卡住，点、拖都没反应（画面还在，只是永远不更新）。

**根因**（`Rubik.vue` 与 `AnimationModel.vue` 一模一样）：

```js
const visibility = new IntersectionObserver(entries => {
  visible && document.visibilityState !== 'hidden' ? start() : stop()
}, { threshold: 0 })

const onVisibilityChange = () => {
  if (document.visibilityState === 'hidden') stop()   // ← 只停，没有任何地方 start()
}
```

- `IntersectionObserver` **只在相交状态变化时回调**。切标签页时元素一直待在视口里，
  `isIntersecting` 从来没变过 → 回来时回调不会再触发。
- `visibilitychange` 的处理函数只写了 `stop()`。
- 结果：rAF 链彻底断掉，但 pointerdown / pointermove 监听、状态机全都还活着 →
  表现为「点了没反应、拖了没反应」，极具欺骗性（不是事件失效，是一帧都不再绘制）。

**修法**：自己记 `inViewport`，把两个信号合并成一个 `applyVisibility()`
（`shouldRun = inViewport && document.visibilityState !== 'hidden'`），两边都调它。

**AnimationModel 额外的坑**：它用 `OrbitControls`。切走时若鼠标正按着，`pointerup`
会丢在别的标签页，OrbitControls 内部 `state` 卡在 `ROTATE` → 回来不按键移动鼠标也会转视角。
处理：只在「由停到跑」那一次 (`if (!running)`) 向 `document` 补发一个
`pointerup(pointerId:1)` 复位，然后 `controls.update()` 补一帧。Rubik 是自己写的拖拽，只需 `drag = null`。

**排查结论**：`Circle.vue` 有 rAF 但没有 IntersectionObserver（从不停），不存在此问题；
只有 Rubik / AnimationModel 两处需要修，现已都改。

## 验证方法（无头 CDP，脚本放 %TEMP%）

伪造可见性就能复现，不需要真的切窗口：

```js
Object.defineProperty(document, 'visibilityState', { configurable: true, get: () => 'hidden' })
document.dispatchEvent(new Event('visibilitychange'))
```

计数用包装 `requestAnimationFrame`，靠回调源码里是否含 `mixer.update` / `cube.update` 区分是哪个组件的 tick。

**两个量测坑**：
1. WebGL canvas 是 `preserveDrawingBuffer:false`，`ctx.drawImage(canvas, …)` /
   `canvas.toDataURL()` 抓到的是**空缓冲**（全透明）→ 想用 alpha 质心证明"视角转了"必然失败。
2. 想用「截图是否相同」证明拖拽生效也不行：Littlest Tokyo 自带帧动画，不拖也会变。
   → 正解：用 Node 内置 `zlib` 自己解 CDP 的 PNG（IDAT inflate + 4 种 filter 反算），
   算平均逐像素差，和「不碰它的两帧基线差」比倍数。实测 base≈1.6 / drag≈8.0（ratio 5.2）。
